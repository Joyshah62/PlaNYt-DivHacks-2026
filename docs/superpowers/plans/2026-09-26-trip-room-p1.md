# Trip Room P1: Foundation and Deciding Together, Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Steps use `- [ ]` checkboxes. Run the named tests after every task and commit.

**Goal:** Move Plan with Friends into a self-contained feature folder. Add "Who's coming?", emoji avatars and group consensus ("I'm in", deadline, automatic lock) in place of the organizer lock. Rebuild the room as the approved dashboard.

**Spec:** `docs/superpowers/specs/2026-09-26-trip-room-design.md`

**Tech:** Next.js 16.3.5 (App Router), React 19.2, TypeScript, Zod 4, Vitest, Tailwind 4, MongoDB driver 7.

## Global constraints

- **Read before writing Next code:** `node_modules/next/dist/docs/01-app/01-getting-started/15-route-handlers.md`. `params` and `searchParams` are Promises.
- Only `src/features/plan-with-friends/bridge.ts` may import `@/lib/*` or `@/components/*`. Enforce this with ESLint.
- App files outside the feature change only in these places:
  - one-line re-exports in `src/app/start`, `src/app/trip/**` and `src/app/api/trips/**`
  - `eslint.config.mjs` (the boundary rule)
  - one link on `src/app/page.tsx`
  - `src/components/plan/Itinerary.tsx` and `PlannerView.tsx`, which already have the link
- Errors return `{ error: string }`. Exact strings: "This plan is locked." · "Join the trip first." · "Vote for a place first." · "Pick an emoji and a color."
- Limits: 10 stops in the day · 30 candidates · names 1–30 characters · at most 12 members per room.
- Comments: none, except a one-line *why*.

### Task 3: Server — members with avatars, confirmations, deadline, automatic lock (TDD)
- [ ] Backend interface:
  - `setMember(id, memberId, member: Member)`
  - `getMembers` returns `Record<string, Member>`; an old string value becomes `{ name, avatar: defaultAvatar(memberId), joinedAt: 0 }`
  - new: `setConfirmation(id, memberId, signature | null)`, `getConfirmations(id)`, `setDeadline(id, at | null)`
  - memory and MongoDB implement all of it. MongoDB uses `$set` / `$unset` on `confirmations.<memberId>`, and `deadline` lives in `meta`.
- [ ] Service:
  - `create({ title, settings, stops, name, avatar })` returns `{ trip, memberId }`. `stops` may be empty. The organizer key is gone.
  - `join(id, name, avatar)`: 409 once locked, 400 when the room already has 12 members.
  - `confirm(id, memberId, on)`: 400 "Vote for a place first." when there's no draft. Otherwise it stores the signature.
  - `setDeadline(id, memberId, at | null)`: `at` must be in the future and within 14 days.
  - `read()` runs `consensus()`. When it says lock, it writes `lockedCode` (and does so only once).
  - `Trip` exposes `consensus` so the UI can show "2 of 3 are in".
- [ ] Schemas and routes:
  - `JoinBody` / `CreateTripBody` take `avatar`. `CreateTripBody` makes `code` optional, adds an optional `date`, and requires `code` or `date`.
  - New `ConfirmBody { memberId, on }` and `DeadlineBody { memberId, at: number | null }`.
  - Add routes `/api/trips/[id]/confirm` and `/api/trips/[id]/deadline`. Delete the `/lock` route and its re-export.
- [ ] Tests:
  - Update `service.test.ts` and `routes.test.ts`: remove the lock tests, and add confirm, deadline, avatar, 12-member cap and empty-room cases.
  - Extend `mongo.test.ts` to cover confirm and lock.
  - Run the live test with `MONGODB_URI`.
- [ ] Commit.
