# Trip Room v3: Implementation Plan

> Execute with superpowers:executing-plans. After each step: list changed files and anything stubbed.

**Goal:** Twelve review changes that make the trip room feel finished:
- clearer onboarding cards
- draggable availability and an overlap clock
- Gemini suggestions shown as cards
- an agent with room tools
- a stored, editable itinerary with drag, regenerate and crowd bars
- a fair meeting spot with agreements

Everything stays inside `src/features/plan-with-friends/`, and the landing page returns to exactly its `main` state.

## Decisions (2026-09-26)

- **The day is built by the existing optimizer.** Votes decide which places go in. There is no Gemini in scheduling. Gemini is used for Ask Roam, the agent, and "Turn into a place".
- **"Open spaces data" means Roam's bundled places:** 29.6k OSM places, including parks, gardens, viewpoints and plazas, plus the 407 subway station complexes. No new data.
- **The landing-page link is removed.** Groups reach the room via `/start`, the itinerary's "Plan with friends" button, or an invite link. `WhoIsComing` stays exported for the colleague's landing redesign.
- **Two people editing at once: the last write wins.** Every itinerary edit stores `editedBy` and `editedAt`. Everyone sees "Edited by {name} · {time}" within one poll (3 s), and Undo reverts it.
- **Identity:** names and emoji stay as they are. The login adapter (`identity.ts`) is unchanged, so the colleague can plug accounts in later.

## Data model additions (`core/types.ts`, stored in trip `meta` unless noted)

```ts
interface MeetingSpot { key: string; name: string; kind: "station" | "park" | "plaza" | "place"; lat: number; lon: number;
  reason: string; perMember: Record<string, number>; worst: number; spread: number }
interface Meeting { spot: MeetingSpot | null; source: "auto" | "manual"; proposedBy: string | null; agreedBy: string[] }
interface Itinerary { order: string[]; manual: boolean; editedBy: string | null; editedAt: number | null; basis: string }
interface UndoEntry { id: string; by: string; label: string; at: number; restore: RoomSnapshot }  // last 10, in meta
```

- `Trip.meeting`: when the spot is automatic, it's recomputed on read. A manual spot is stored. Agreements belong to a specific spot key, so a new spot clears them.
- `Trip.itinerary`, `Trip.tray` (voted places not scheduled) and `Trip.stale`:
  - `stale = itinerary.manual && itinerary.basis !== currentBasis`.
  - The basis is a hash of the vote ranking, the overlap window and the meeting spot.
  - An itinerary that was never edited by hand is rebuilt automatically whenever the basis changes.
- **Picking the auto itinerary:** take places in vote order, and add each one while its visit time plus the estimated travel still fits the window. The optimizer then orders and times the chosen set.
- Candidates gain an optional `note` (the "why").

## Steps

### Step 1–4: Onboarding cards, availability, overlap clock
1. **Header subline:** exactly `{n} person|people · hosted by {host}`.
2. **Starting-point card:**
   - Title "Where are you coming from?", plus the new description.
   - A "Use my location" chip (`navigator.geolocation`; only the server rounds and stores it).
   - Collapsed state: "📍 Near {area} · change".
   - A line saying "{x} of {n} people have added a start".
   - Remove the map's banner.
3. **Availability:**
   - A `TimeRangeSlider` with two handles in 30-minute steps, usable by keyboard and pointer.
   - Copy: "Group overlap: {start} – {end}", or "No time works for everyone yet" plus who's blocking it.
   - People who haven't set availability show "not set" and are left out of the calculation.
4. **Overlap clock** (`OverlapClock`):
   - An SVG dial with one arc per member, their avatar at the end of the arc, and the overlap highlighted.
   - With more than 5 members, or arcs that overlap too much, it falls back to stacked horizontal bars.
   - The overlap window already drives the day (P5).
5. Remove the landing-page link.

### Steps 5, 7, 8: Suggestions
- **`SuggestionCarousel`:** an isolated component, `{ items: SuggestionItem[]; onAdd(item); addedKeys; loading; error }`. Each card has a photo, name, neighborhood, category, a crowd hint and "+ Add".
- **Ask Roam** calls a feature route, `POST /api/trips/[id]/ask`. It sends Gemini (reusing `/api/assistant`'s model and client) the room context:
  - coarse areas only
  - the overlap window
  - places and their votes
  - the current itinerary
  - the meeting spot

  Results come back as carousel items.
- **Manual suggest:** place search with a photo preview, plus an optional "why" note. If the place already exists, it gets an upvote instead of a duplicate (already the case).
- **Turn into a place:** `POST /api/trips/[id]/ideas/suggest`. Gemini works out the intent, and Discover then finds 3–5 places near the meeting spot, shown in the carousel. The place that gets added is credited to the note's author, and the note shows "→ added as {place}". If the note names a specific place, the flow skips straight to a confirm step.

### Steps 9–11: The day
- **Two zones:**
  - "The day": a timeline built from the stored itinerary, planned with `keepOrder`.
  - "Also in the running": the tray.
- **Drag and drop** with native pointer events plus keyboard buttons (↑ ↓ remove), no library:
  - drag from the tray into the timeline
  - reorder within the timeline
  - drag out to send a place back to the tray

  Every drop saves the new order through `POST /api/trips/[id]/itinerary` and replans. Edits are refused after the lock.
- **Warnings:** if the day runs past the window, show a warning but don't block it. The first leg shows its origin, e.g. "14 min walk from meeting spot". Show "Edited by {name} · {time}".
- **Regenerate:** a button, plus the stale banner "Votes and times changed since this plan was made · Regenerate".
- **Crowd bars:** a `CrowdStrip` on each stop with its time slot highlighted, next to the existing label.

### Step 12: Meeting spot
- The server scores candidates: the stations and parks/plazas nearest the members' middle point, ranked by the longest trip and then the spread.
- The card shows:
  - the name and a one-line reason
  - each member's travel time
  - "Agree with meeting spot"
  - "{x} of {n} agree", with avatars
- **Manual proposals:** any member can propose a spot by searching or tapping the map. That clears agreements and marks the itinerary stale.
- **Map:** members' area markers only. The draft day starts at the meeting spot. This replaces the P2 "fair first stop" and the voted meetup candidate; the old meetup candidates still read correctly.

### Step 6: Agentic Ask Roam
- **Tools:** `search_places`, `add_place`, `remove_place`, `reorder_itinerary`, `replace_itinerary_item`, `set_meeting_spot` and `regenerate_itinerary`.
- The server runs each tool as the member who asked. Before each action it saves an undo entry, and the UI shows "{name} swapped MoMA for the Whitney · Undo".

## Edge cases
- **Host alone:** the overlap is the host's own window, the meeting spot is at the host's area, and "I'm in" locks the plan (the bar already warns about this).
- **Members missing a start or availability:** they're left out of the calculation and shown as "not set".
- **No overlap:** show the majority window and name who's blocking it.
- **0 voted places:** the empty-state timeline says "Vote for a place to build the day". **1 voted place:** a one-stop day.
- **Gemini or API failures:** show a spinner while waiting and a readable message on failure. The room keeps working without Gemini.

## Done when
- Two browsers (as different members) see each other's changes live.
- Ask Roam and Turn into a place return real bundled places.
- The day fits the overlap window and supports drag, reorder, regenerate and crowd bars.
- The map shows a fair meeting spot and agreement works.
- No exact location ever reaches another browser.
- `src/app/page.tsx` is identical to `main`.
